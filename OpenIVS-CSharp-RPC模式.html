Why RPC

解决冲突，同时保留本机调用效率

01 / ISOLATION

CUDA 与 DLL 不再撞车

CCD 软件和 DLCV 推理服务各自在自己的进程中加载依赖。一个环境的升级，不要求另一个环境同步替换。

02 / THROUGHPUT

大图不塞进 JSON

命名管道只传动作、尺寸、参数和共享内存令牌；图像像素直接放入本机共享内存，避免 Base64 膨胀与网络传输。

03 / ADOPTION

调用改动很小

仍通过 OpenIVS 的 Model 类加载与推理，只需启用 rpc_mode，服务探活与启动由 API 处理。

Call Flow

一次推理请求如何完成

控制消息走命名管道，体积较大的图像与 mask 走共享内存，两类数据各走适合自己的通道。

01

CCD 软件创建模型

以 RPC 模式构造 OpenIVS C# Model，传入模型路径与 GPU 设备编号。

Model(path, deviceId,
rpc_mode: true)
02

检查并启动服务

客户端向本机管道发送 ping。服务不可用时启动 AIModelRPC.exe，等待探活成功。

PIPE · DlcvModelRpcPipe
ACTION · ping
03

在独立进程加载模型

模型路径和设备编号通过 JSON 发给 RPC 服务，DLCV 推理 DLL 只在服务进程中加载。

ACTION · load_model
model_path + device_id
04

图像写入共享内存

C# API 规整图像后创建本机内存映射，将连续像素写入映射区，并生成唯一 token。

DlcvModelMmf_<token>
width × height × channels
05

发送轻量推理指令

管道消息只包含共享内存 token、图像尺寸、通道数与推理参数；服务据此打开同一映射区。

ACTION · infer
mmf_token + params_json
06

返回结构化结果

检测结果通过 JSON 返回；较大的 mask 可通过独立共享内存读取，再恢复为 C# 结果对象。

JSON · bbox / score / class
MMF · DlcvModelMask_<token>
07

释放远端模型

CCD 软件释放 Model 时发送 free_model，由 RPC 服务清理对应模型资源。

ACTION · free_model
model_path
Integration

C# 接入只需开启 RPC 模式

CCD 软件调用示例C#
using DlcvModules;
using Newtonsoft.Json.Linq;

var modelPath = @"D:\models\inspect.dvt";

// 第三个参数开启 RPC 模式
using (var model = new Model(
    modelPath,
    deviceId: 0,
    rpc_mode: true))
{
    var options = new JObject
    {
        ["threshold"] = 0.5,
        ["with_mask"] = true
    };

    var result = model.Infer(rgbMat, options);
    // 继续执行 CCD 软件的 OK / NG 逻辑
}
当前协议事实OpenIVS
支持的普通模型DVT / DVO；DVP 与 DVS 后缀按各自模式优先处理。
命名管道DlcvModelRpcPipe，UTF-8 单行 JSON 请求与响应。
RPC 动作ping、load_model、get_model_info、infer、free_model。
图像共享内存DlcvModelMmf_<token>。
Mask 共享内存DlcvModelMask_<token>。
服务程序查找优先调用程序目录，其次 DLCV C# SDK 固定安装目录。
当前批量行为RPC 批量输入由客户端逐张发送并合并结果。
性能说明：共享内存避免了图像 Base64 编解码和网络传输，但客户端仍会把 Mat 像素复制到内存映射区，因此应表述为“低开销本机 IPC”，而不是严格零拷贝。最终耗时仍包含图像复制、进程调度和模型推理。
