# OpenIVS 日志专题文档

## 文件日志位置

“程序目录”指可执行文件所在目录；“工作目录”指当前进程的工作目录，两者不一定相同。

| 组件 | 默认日志位置 | 启用方式 |
| --- | --- | --- |
| C API | `%TEMP%\dlcvInfer_c_api_debug.log` | 没有日志开关 |
| DlcvTest 推理诊断 | `<程序目录>\logs\infer_debug.log` | 默认关闭；环境变量 `DLCV_INFER_DIAG=1/true/yes` 开启 |
| OpenIVS2 运行日志 | `<程序目录>\Logs\OpenIVS-2026_yyyyMMdd.log` | `EnableRuntimeLog`，默认开启；目录可由 `RuntimeLogDirectory` 配置 |
| OpenIVS2 生产日志 | `<程序目录>\ProductionLogs\yyyyMMdd.csv` | `EnableProductionLog`，默认开启；目录可由 `ProductionLogDirectory` 配置 |
| HalconDemo | `<程序目录>\logs\log_yyyyMMdd_HHmmss.txt` | 启动时创建，最低记录级别为 Info，没有界面关闭开关 |
| DlcvCamDemo | `<工作目录>\logs\log_yyyyMMdd_HHmmss.log` | 首次使用 Logger 时创建，没有日志开关 |
| SimpleLogger / SimpleLoggerTest | 默认 `<工作目录>\logs\log_yyyyMMdd_HHmmss.txt` | 创建 Logger 时生成文件；调用方可传入其他目录 |
| C# 控制台 all-tests | `%TEMP%\OpenIVS-DlcvCSharpTest-<GUID>-all-tests.log` | 显式执行 `all-tests` 时创建；可通过位置参数指定日志路径 |

C API 的实际目录以当前进程 `GetTempPathW()` 返回值为准，C# 控制台测试使用 `Path.GetTempPath()`；表中 `%TEMP%` 表示常见临时目录位置。文件名中的日期与时间字段在运行时替换，`OpenIVS-2026_` 是运行日志的固定前缀。

## C API 诊断日志

`dlcv_infer_cpp.dll` 的 C API **正常推理不会逐次写入该文件**。Debug、Release 都执行相同逻辑，每条记录追加后立即关闭文件，没有自动轮转或定期清理。

### 写入时机

模型加载记录来自 `dlcv_infer_cpp_load_model_c`；`dlcv_load_model_c` 调用相同入口。

| 操作或情况 | 是否追加 | 记录内容 |
| --- | --- | --- |
| 模型加载开始 | 是 | `load_model begin`，包含设备编号、模型路径、路径字节十六进制及 UTF-8/GBK 解码诊断 |
| 模型加载成功 | 是 | `load_model success`，包含模型索引；正常加载通常共两条记录 |
| 模型加载失败 | 是 | `load_model failed`，包含失败原因；空路径指针直接记录失败，不记录开始 |
| 结构化推理成功 | 否 | `dlcv_infer_cpp_infer_c`、`dlcv_infer_cpp_infer_with_params_c` 和 `dlcv_infer_c` 没有逐次日志 |
| JSON 推理成功 | 否 | `dlcv_infer_cpp_infer_json_c` 和原生 JSON 转发入口 `dlcv_infer` 没有逐次日志 |
| 原生转发接口的异常 | 是 | 异常到达 `CallNativeString`、`CallNativeInt` 或 `CallNativeVoid` 的捕获分支时，通过 `RecordNativeApiFailure` 记录接口名称和异常信息；包括推理、模型信息、设备查询等接口 |
| 模型或结果释放失败 | 部分情况记录 | 原生模型释放返回失败、结果释放抛出异常等路径也调用 `RecordNativeApiFailure` |

**并非所有推理失败都会写入日志。** 结构化推理内部捕获的错误主要通过 `DlcvCResult.code/message` 返回；扩展 JSON 推理内部捕获的错误通过空返回值和 `dlcv_infer_cpp_get_last_error_c()` 返回。原生 JSON 推理中已经转换为错误 JSON 的分支也不会仅因返回失败而追加日志。

每条日志包含本地时间和 `[dlcvInferCAPI]` 前缀。排查失败时应同时检查接口返回结果，而不是只依赖该文件。

源码：[C API 实现](../dlcv_infer_cpp/dlcv_infer_c_api.cpp)；接口说明：[C API 文档](C%20API文档.md)。

## DlcvTest 推理诊断

- 开关值忽略大小写并去除首尾空白；未开启时，单图推理不写该诊断文件。
- 开启后，正常单图推理记录开始与结束，内容包括图片名称、模型路径、图像尺寸、推理参数、结果数量和耗时；DVP 模式会额外发送一次 HTTP 诊断推理请求并记录响应摘要。自测模式不调用这些单图诊断入口。
- 追加写入 UTF-8 文本，没有自动轮转或定期清理。该开关控制的是诊断日志，不是只记录失败的开关。

源码：[诊断开关与写入](../DlcvTest/Views/MainWindow/MainWindow.Diagnostics.cs)、[单图推理调用](../DlcvTest/Views/MainWindow/MainWindow.Infer.cs)。

## OpenIVS2

### 运行日志

- 记录启动、模型、相机、运行周期结果和异常；正常检测周期也会写入，不是仅失败日志。
- 按日期创建文件，以 UTF-8 无 BOM 追加。已有日志再追加将超过配置大小上限时，将旧文件改名为带时间后缀的文件，再创建当前文件。
- 默认 `RuntimeLogMaxFileSizeMB=10`、`RuntimeLogMaxFileCount=7`；写入后按更新时间删除超出数量限制的同前缀日志文件，数量包含当前文件和轮转文件。

### 生产日志

- 每个检测周期完成后追加一行，包括时间、时间戳、相机 A～F 的 OK/NG 与总结果；未启用的相机写 `-`。
- 按日期分文件，使用 GBK 编码；文件首次创建时写 CSV 表头，没有按大小轮转或自动清理。

源码：[默认设置](../OpenIVS2/Models/AppSettings.cs)、[运行日志](../OpenIVS2/Services/RuntimeLogService.cs)、[生产日志](../OpenIVS2/Services/ProductionLogService.cs)、[周期与日志调用](../OpenIVS2/MainWindow.xaml.cs)。

## HalconDemo

- 记录启动和关闭、相机操作、模型加载、单张图片推理完成及异常。
- 实时推理每完成 100 帧记录一次性能统计，不是每帧记录成功日志；重复异常仍会继续记录。
- 使用 SimpleLogger 追加写入 UTF-8 文本，没有自动轮转或定期清理。

源码：[日志初始化与调用](../HalconDemo/Form1.cs)、[SimpleLogger](../SimpleLogger/SimpleLogger.cs)。

## DlcvCamDemo

- 记录设备枚举和打开、采集错误、显式保存图片及相关异常，没有正常推理逐次成功日志。
- 按 Logger 初始化时的时间命名，之后追加到同一文件；没有自动轮转或定期清理。

源码：[Logger](../DlcvCamDemo/logger.cs)、[设备与采集调用](../DlcvCamDemo/utilsCamera.cs)、[界面调用](../DlcvCamDemo/Form1.cs)。

## SimpleLogger 与控制台测试

- SimpleLogger 按调用追加日志，可设置最低日志级别；`consoleOutput=false` 只关闭控制台输出，不关闭文件写入。库本身没有自动轮转或清理，SimpleLoggerTest 提供清空当前日志的操作。
- `all-tests` 的默认文件名每次带新 GUID，记录本次控制台测试结果，没有自动清理；指定已有日志路径时覆盖写入，不追加；路径用法见 [C# 模型测试工程文档](C%23模型测试工程开发文档.md)。

- 完整验证入口 `Test/DlcvCSharpTest/RunAllTests.ps1` 默认也将总日志写入系统临时目录，并生成同一前缀的 `OpenIVS-DlcvCSharpTest-<GUID>-managed.log`、`-stdout.log`、`-stderr.log`，用于收集托管日志、标准输出和标准错误；脚本结束时清理这三份中间文件，自定义总日志路径也必须在系统临时目录。

源码：[SimpleLogger](../SimpleLogger/SimpleLogger.cs)、[日志演示程序](../SimpleLoggerTest/Form1.cs)、[all-tests](../Test/DlcvCSharpTest/Program.cs)、[完整验证脚本](../Test/DlcvCSharpTest/RunAllTests.ps1)。

## 界面与控制台输出

`Console.WriteLine`、`Debug.WriteLine` 和界面中的日志列表不等于文件日志；是否落盘取决于对应组件是否调用上述文件写入实现。命令行重定向或测试程序捕获输出时，输出文件由调用方指定。
