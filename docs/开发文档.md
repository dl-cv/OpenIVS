# 开发文档

## 文档规则

- 文档只记录项目当前实现与运行事实。
- 文档不写建议、猜测、规划、风险判断、设计理由、判定依据。
- 文档不写问答式内容，不直接回答对话中的临时问题。
- 文档不写历史、过程、修改记录、拆分说明。
- 文档不写重复内容；同一事实只在最合适的位置出现一次。
- 文档不写第一人称、第二人称对话。
- 文档规则只保留在本文件，子文档不重复书写规则。
- 文档正文只描述项目本身，不写对话提示词、写作要求和编写过程。
- 目标：任何开发者仅依据本文档，都能实现一个功能与用户体验一致的程序。允许代码结构不同，但最终呈现给用户的功能、交互、输出文本与可视化效果必须一致。

## 工程关系

- `DlcvCsharpApi` 为 `DlcvDemo`、`DlcvDemo2`、`DlcvDemo3` 和 `Test/DlcvCSharpTest` 提供 C# 推理接口，直接调用进程内实际加载的 `dlcv_infer.dll` 或 `dlcv_infer_v.dll`；共享 index 不依赖 `dlcv_infer_cpp.dll`。
- `dlcv_infer_cpp` 为 `dlcv_infer_cpp_qt_demo`、`dlcv_infer_cpp_qt_demo2`、`dlcv_infer_cpp_qt_demo3`、`dlcv_infer_c_qt_demo`、`Test/dlcv_infer_cpp_test` 和 `Test/dlcv_infer_c_test` 提供 C++ 与 C 推理接口。
- `dlcv_infer_cpp/ZXingRuntime.targets` 由该 DLL 工程导入；Qt Mask 测试的 `.props/.targets` 位于 `Test/qt_demo/`。跨项目共用的运行库复制规则位于 `build_script/DlcvNativeRuntime.targets`。
- `dlcv_infer_cpp` 的 C API 源码与 C++ API 源码位于同一工程，统一生成 `dlcv_infer_cpp.dll` 和 `dlcv_infer_cpp.lib`。C 调用端只包含 `dlcv_infer_c_api.h`；C Qt Demo 通过 `LoadLibraryW` 和 `GetProcAddress` 动态调用 C 接口。
- `模块、流程与模型推理标准文档.md` 记录两套 API 共用的对象语义与流程语义，语言文档不重复展开同一事实。

## 统一编译说明

- 本仓库所有编译、构建、重建与发布前构建验证统一通过项目级 skill 脚本 `build_script/build.py` 执行。
- 默认构建目标为仓库根目录 `OpenIVS.sln`。
- 指定单个 C# 项目时，构建对应 `.csproj`。
- 默认构建参数为 `Debug`、`x64`、`Build`、`minimal`。
- 用户明确指定 `Release`、`Rebuild`、`Clean` 等参数时，按指定值执行。
- 不直接使用 `msbuild`、`dotnet`、`powershell` 或其他本地 shell 编译命令。
- 构建目标、输出目录与运行入口仍以各子文档记录的工程文件、解决方案和产物为准。
- 本节为各子文档中编译说明的统一引用位置。

## C# 正式编译、打包与安装

- C# 测试程序的正式编译打包入口为仓库根目录 `1_编译打包.bat`，该脚本在仓库根目录调用 `python -m build_script.build_package` 并返回实际构建状态。
- `build_script/build_package.py` 依次同步程序集版本，通过 `build_script/build.py` 以 `Release`、`x64`、`Build`、`minimal` 构建 `DlcvDemo/DlcvDemo.csproj`，重建 `dlcvpro_infer_csharp` 暂存目录，按发布文件清单复制主程序及托管运行库，从当前 Python 环境已安装的 `dlcvpro_infer_csharp` 包复制 `AIModelRPC.exe`，从当前用户证书存储选择唯一有效的代码签名证书，签名 `C# 测试程序.exe` 与 `AIModelRPC.exe`，并通过 `build_script/setup.py bdist_wheel` 在 `dist/` 生成 wheel。C# wheel 不复制 `dlcv_infer_cpp.dll` 或其 OpenCV 运行库；内部构建产物 `DlcvDemo.exe` 及对应配置文件不进入 wheel。
- `python -m build_script.build_package --install` 在完成上述步骤后，使用当前 Python 环境的 `pip --force-reinstall` 安装本次生成的 wheel。
- `2_安装新版.bat` 从脚本所在目录的 `dist/` 按修改时间选择最新 wheel。无参数时先尝试卸载当前 `dlcvpro_infer_csharp`，随后安装 wheel；卸载失败仍继续安装。安装后保留 `pause`，最终返回安装的 pip 状态码，不单独返回卸载状态码。
- `2_安装新版.bat --target "目标目录"` 使用当前 Python 的 `python -m pip install --no-deps --upgrade --target`，不卸载共享环境中的包，不执行 `pause`；相对目标路径按调用目录解析。此模式复用现有 Python 与依赖，不创建 Python 环境。缺少目标路径返回 `2`，缺少 `dist/` 或 wheel 返回 `1`，pip 失败返回其错误码。
- `python -B Test/test_install_target.py` 在系统临时目录运行原脚本副本和临时 `PYTHONPATH` 中的假 `pip.py`，检查参数、目标路径、工作目录、默认分支及退出码；仅验证命令构造和状态，不执行真实安装，也不证明包可安装或可运行。
- 编译打包脚本任一步骤失败时以非零状态退出；成功时输出最终 wheel 路径和安装状态。
- Qt 测试程序不进入 C# wheel。C++ API 程序构建 `dlcv_infer_cpp_qt_demo/dlcv_infer_cpp_qt_demo.vcxproj`，C API 程序构建 `dlcv_infer_c_qt_demo/dlcv_infer_c_qt_demo.vcxproj`；两者使用 `dlcv_infer_cpp.dll` 和 `dlcv_infer_cpp.lib`。

## C++ Qt 测试程序分发包

- `1_编译打包(C++).bat` 在仓库根目录调用 `python -m build_script.build_cpp_package`，通过 `build_script/build.py` 构建 `dlcv_infer_cpp_qt_demo/dlcv_infer_cpp_qt_demo.vcxproj` 的 `Release/x64`，其工程引用同时构建 C++ API DLL。构建子进程设置 `DlcvUseSharedQt=true`，EXE 输出到 `temp/cpp-qt-shared/`，中间文件位于 `temp/cpp-qt-shared-obj/`。
- 暂存目录为 `dlcvpro_infer_cpp/`，主程序名称为 `C++ 测试程序.exe`。按固定清单收集主程序、`dlcv_infer_cpp.dll` 和 `hasp_26146.ini`，共三个文件。`build_script/build_package.py` 仅负责 C#；C++ 脚本复用其中的证书查询与签名配置。
- C++ 使用独立的 `build_script/setup_cpp.py`，版本变量为 `version`；通过 `bdist_wheel` 生成 wheel，产物位于 `dist_cpp/`，构建缓存位于 `build_cpp/`。两个 setup 固定各自包名、版本和目录，均使用现有 Python 环境。
- `2_安装新版(C++).bat` 安装 `dist_cpp/` 中最新的 `dlcvpro_infer_cpp-*.whl`；`--target "目标目录"` 使用现有 Python 将包安装到指定目录。安装后运行包目录中的 `C++ 测试程序.exe`，无参数显示原有 Qt 界面，也可使用现有 `infer` 和 `ui-test` 参数。
- 运行环境使用已安装深度视觉 SDK、模型授权及 Visual C++ 运行库。OpenCV 4.10.0 和 Qt 6.10.2 主 DLL 从环境 PATH 中的 `C:\dlcv\bin` 加载；Windows 平台插件使用该目录中的 `qwindows.dll`，样式插件使用 `styles/qmodernwindowsstyle.dll`。C++ 读码模块优先加载 `dlcv_infer_cpp.dll` 同目录的 `ZXing.dll`，失败后尝试 `C:\dlcv\bin\ZXing.dll`。共享 Qt 与 `Qt6_DIR` 对应编译版本一致；包内无 Qt 或 ZXing 文件。
- 分发构建启用 `DLCV_SHARED_QT_RUNTIME`，程序在创建 QApplication 前加入共享插件目录。显式设置的 `QT_QPA_PLATFORM_PLUGIN_PATH` 保持有效，供已有非交互验证入口使用；普通工程构建继续使用原有 Qt 复制规则。
- `3_上传wheel(C++).bat` 将 `dist_cpp/` 中最新的 C++ wheel 上传到已配置的 `dlcvpro` 源。

## 四图共享模型并发回归

`Test/FourImageConcurrencyRegression/FourImageConcurrencyRegression.csproj` 为独立 x64 控制台工程，仅引用正式 `DlcvCsharpApi` 及现有 OpenCvSharp、Newtonsoft.Json 依赖。构建入口：

```text
python build_script/build.py Test/FourImageConcurrencyRegression/FourImageConcurrencyRegression.csproj
```

运行入口：

```text
Test/FourImageConcurrencyRegression/bin/x64/Debug/FourImageConcurrencyRegression.exe --model <模型绝对路径> --images <四图目录绝对路径> --output <现有工作目录绝对路径> --rounds 3000 --serial-rounds 200 --device 0
```

- `--model`、`--images`、`--output` 必填，路径中的环境变量须在启动前展开；图片目录包含 `A.bmp`、`B.bmp`、`C.bmp`、`D.bmp`。`--output` 指向现有工作目录，程序在其中自动创建 `yyyyMMdd_HHmmss_fff_进程编号` 时间目录保存结果，不覆盖既有日志。
- `--rounds` 默认 `3000`，`--serial-rounds` 默认 `200`，`--device` 默认 `0`。测试固定使用工程引用生成的正式 `DlcvCsharpApi.dll`，推理 DLL 按正式 API 的搜索规则加载；摘要记录实际 C# API 与推理 DLL 路径和版本。修复前后对照使用相同测试 EXE 和 C# API，分别加载对应推理 DLL。
- 全程复用一个 `Model` 实例。先生成四路串行基准，核查 A、C、D 均无目标，B 仅有 `C2沾污`、分数 `0.60400390625`（容差 `1e-6`）；随后每轮依次验证四图，共 `200` 轮。
- 图片加载时一次性从 BGR 转为 RGB 并保存初始内容 SHA-256。每次推理仅 `Clone()` 对应 RGB 图像，调用前和调用后分别核查副本尺寸、类型及逐行内容哈希，输入被改写时记录异常并返回非零。
- 并发阶段每轮创建四个 `Task`，全部到达等待点后通过同一个 `ManualResetEventSlim` 同时放行。每路独立复制 RGB 图像，全部完成、比较并写日志后才进入下一轮。
- 每次结果按内容排序，与对应串行基准精确比较目标数量、类别编号和名称、分数、框、面积、角度及 mask 的尺寸、类型和逐行内容 SHA-256。每次推理后释放返回 mask 和 RGB 副本，测试结束时释放四张 RGB 原图。
- 输出无 BOM UTF-8 的 `results.jsonl` 和 `summary.json`。逐次日志包含阶段、轮次、图片、实际结果、输入校验、不一致时的基准及异常；摘要包含实际 API、推理 DLL、RGB 输入哈希、完整基准、已完成轮数、串行及并发不一致数、异常数及耗时。每 `250` 轮及阶段结束输出进度。
- 不一致会保留证据并继续完成后续轮次；并发异常在当前轮四路全部结束并写入日志后退出。成功返回 `0`，运行异常、样例基准不符或结果不一致返回 `1`，参数错误返回 `2`。

## 大图显示回归

`Test/ImageViewerDisplayTest/ImageViewerDisplayTest.csproj` 为独立 x64 WinForms 控制台工程，引用正式 `ImageViewer` 与 `DlcvCsharpApi`，不加载模型和推理 DLL。构建入口：

```text
python build_script/build.py Test/ImageViewerDisplayTest/ImageViewerDisplayTest.csproj
```

运行入口：

```text
Test/ImageViewerDisplayTest/bin/x64/Debug/ImageViewerDisplayTest.exe <输出目录绝对路径>
```

- 使用 24000×24000 三通道原图、普通框与完整原图 Mask，检查适配、放大、原图单像素细节、视区边缘及原尺寸导出；导出检查包含分块边缘像素与 Mask。
- 使用 1000×24000 长条图验证底部原像素和 Mask 的位置；使用 28301×20283 灰度图验证非正方形超大图；使用 1600×900 四通道图与局部 Mask 验证原有通道转换、ROI 映射和保存尺寸。
- 在 1200×800 面板连续移动视区并通过 `DrawToBitmap` 完成 12 帧实际绘制，记录平均耗时，回归上限为 100 毫秒/帧。底图断言检查无 Mask 覆盖区域的已知颜色。
- PNG 与无 BOM UTF-8 `result.json` 写入指定输出目录；成功返回 `0`，渲染异常或任一检查失败返回 `1`。该工程验证控件像素和绘制耗时，完整程序的模型推理及窗口操作另行验收。

## 三个桌面项目的构建验证

`DlcvDemo/DlcvDemo.csproj`、`DlcvTest/DlcvTest.csproj` 和 `OpenIVSWPF/OpenIVS.csproj` 均通过项目 `build.py` 单独构建，默认 Debug x64，三个项目串行执行。

`DlcvTest` 和 `OpenIVSWPF` 使用 PackageReference。直接执行旧的纯 Build 时，曾因已有 assets 缺少 win-x64 目标而失败；构建入口对这类 C# 工程在 Build/Rebuild 时增加 `/restore`，由 MSBuild 先还原再重新求值并构建。两个项目实际复验通过，未增加 RuntimeIdentifiers 字段，也未手工修改生成的 assets 文件。

非交互回归入口为 `Test/run_desktop_project_regression.py`，参数如下：

```text
python Test/run_desktop_project_regression.py --demo-exe <DlcvDemo.exe> --dlcvtest-exe <DlcvTest.exe> --wpf-exe <OpenIVSWPF.exe> --api-dll <本次构建的DlcvCsharpApi.dll> --model-root <测试模型目录> --core-dll-directory <推理DLL目录> --output <系统临时目录/report.json>
```

- 三个实际 EXE 串行执行。DlcvDemo 使用已有 infer 和 ui-test，ui-test 固定 interactive-dialogs=false；两个 WPF EXE 使用 `selftest --model-root <目录> --output <临时目录/result.json>`。
- 固定猫狗分类 DVT 与气球实例分割 DVT，检查数量、类别、分数（容差 1e-6）、实际控件 PNG 和重复释放。两个 WPF 的测试实现位于 Test/desktop_projects，以 Compile Link 编译进各自 EXE，不增加 SDK 测试导出。
- DlcvTest 调用正式窗口的模型加载、单图推理与 WPF 控件内存绘制；OpenIVSWPF 调用正式 ModelManager、图像显示方法及 ImageViewer 内存绘制。自测不显示常规主窗口，不初始化相机、PLC、主循环、生产配置或模型历史读写，也不运行网络诊断。
- WPF 的常规 StartupUri 只在非自测分支设置，测试构造的窗口不执行常规关闭回调。无参数仍启动原应用；自测用例、结果写入、退出码和固定模型规则不进入生产 SDK。
- 测试仅覆盖上述模型推理、显示和释放，不代表相机采集、PLC 通信、完整主窗口交互或压力测试通过。所有日志和图像只写入系统临时目录。


## Sentinel 独立 C# 管理工具

`Test/SentinelManager` 为 .NET Framework 4.7.2、x64 的独立 WinForms 工程，在 `OpenIVS.sln` 中归入 `Test` 分组，不引用 Python、Qt、推理 SDK 或厂商授权 DLL。运行程序为 `SentinelManager.exe`。

提供本机 Sentinel HL 普通硬件设备与 Feature 查询、创建 LMID、关闭三项网络访问、本地服务补丁和一键修复。启动窗口不访问服务；修改操作先显示确认提示。查询遇到服务停止时按权限启动服务；本地补丁覆盖当前用户配置并重启 `hasplms`，可能短暂中断授权连接。程序不保存或处理 ACC 密码，不实现授权签发或加解密。

- 工程运行：使用 Visual Studio 打开 `OpenIVS.sln` 并选择 `SentinelManager` 为启动项目；命令行日常编译使用共享 `build.py`，不提供独立打包或安装入口。
- 窗体编辑：`Test/SentinelManager/SentinelManagerForm.Designer.cs` 定义控件及初始布局，`.resx` 保存资源，`SentinelManagerForm.cs` 保留操作逻辑。无参数构造入口供设计器加载，测试构造入口继续支持注入客户端；测试程序的 `designer-test` 命令检查 WinForms DesignSurface 加载与控件。
- 版本：`Test/SentinelManager/Properties/AssemblyInfo.cs` 为本组件唯一版本来源；C# 分发包的 `build_script/setup.py` 和推理程序集不变。
- DPI：`Test/SentinelManager/App.config` 启用 PerMonitorV2；窗体以 96 DPI 设计并自动缩放，字体使用点单位。运行配置文件须与程序放在同一目录。`Test/run_sentinel_dpi_regression.py --output-dir <系统临时空子目录> --expected-native-dpi 144` 分别验证本机 150% 与独立进程 96 DPI 虚拟化环境，不更改系统设置，不代表物理显示器切换测试。
- 后端验证：`Test/SentinelManagerTest/bin/Release/SentinelManagerTest.exe`，仅使用可替换传输、服务命令与系统临时目录。
- 界面验证：同一测试程序执行 `ui-test --output-dir <系统临时子目录>`，只使用固定数据，不弹确认对话框；输出 `ui-test-results.json` 和初始、结果、原始结果、紧凑布局四张 PNG，退出码非零表示失败。

完整操作说明见 [Sentinel 管理工具](Sentinel管理工具.md)。真实设备、真实 LMID 变更和真实服务重启须在明确授权的人工验收中执行，隔离测试不代表这些操作已在真实设备上验证。
