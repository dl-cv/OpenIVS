# 在其他 Visual Studio 解决方案中引用 dlcv_infer_cpp

适用于把 `dlcv_infer_cpp` 工程加入自己的解决方案、以源码方式调用 C++ 接口（`namespace dlcv_infer` 下的 `Model`、`Result` 等）。

## 目录结构

用打包脚本生成自包含目录：

```cmd
python build_script\package_cpp_source.py --output <目标目录>
```

生成 `<目标目录>\dlcv_infer_cpp`，里面包含源码工程和 `build` 子目录（`WindowsSdk.props`、`DlcvProInfer.props`、`OpenCvVersion.props`、`OpenCvDiagnostics.targets`）。把这个目录复制到你的解决方案根即可，不再需要同级的 `build_script`。

```text
你的解决方案\
  dlcv_infer_cpp\            （源码工程 + build 子目录）
  third_party\               （可选）
    zxing-cpp\bin\ZXing.dll  （本机放置，不入库）
```

仓库内直接构建时 `dlcv_infer_cpp` 使用仓库根的 `build_script`；复制到外部时使用自身的 `build` 目录，两种布局都支持。手工复制时确保 `dlcv_infer_cpp\build` 下有那 4 个文件，只有 `dlcv_infer_cpp` 而没有 `build` 目录会报 MSB4019。

ZXing.dll 按 `DLCV_ZXING_DLL` 环境变量、`third_party\zxing-cpp\bin`、工程目录、`C:\dlcv\bin`、NuGet 包依次查找。

## 依赖

| 依赖 | 配置方式 |
| --- | --- |
| OpenCV 4.x | 设置 `OpenCV_DIR`、`OPENCV_INCLUDE_DIR`、`OPENCV_LIB_DIR`，或安装到 `C:\OpenCV\build`，或放入同级 `third_party\opencv\build` |
| dlcvpro_infer 头文件（json.hpp） | 安装 dlcvpro_infer 包后设置 `DLCVPRO_INFER_INCLUDE`，或放入同级 `third_party\dlcvpro_infer\include`，或使用 `C:\dlcv\Lib\site-packages\dlcvpro_infer\include` |
| ZXing.dll | 按 `DLCV_ZXING_DLL`、`third_party\zxing-cpp\bin\ZXing.dll`、工程目录、`C:\dlcv\bin\ZXing.dll`、NuGet 包的顺序查找 |

ZXing 只在生成结束时复制，不参与编译；所有位置都找不到时报“缺少 ZXing.dll”。

## 你的工程设置

`dlcv_infer.h` 的公开接口大量使用 `cv::Mat` 和 `json`，调用方工程需要 OpenCV 和 dlcvpro_infer 的头文件，并链接 OpenCV 库。

1. 用“添加现有项目”把 `dlcv_infer_cpp\dlcv_infer_cpp.vcxproj` 加入解决方案，再从你的工程添加项目引用。项目引用会自动按配置构建 `dlcv_infer_cpp` 并把 `dlcv_infer_cpp.lib` 加到链接。
2. 你的工程附加包含目录：

   ```
   $(SolutionDir)dlcv_infer_cpp
   OpenCV 的 include 目录
   dlcvpro_infer 的 include 目录
   ```

   解决方案根有 `build_script` 时，可以在工程里导入共享属性表，直接用解析好的路径：

   ```xml
   <Import Project="$(SolutionDir)build_script\OpenCvVersion.props" />
   <Import Project="$(SolutionDir)build_script\DlcvProInfer.props" />
   ```

   附加包含目录写 `$(SolutionDir)dlcv_infer_cpp;$(OpenCvIncludeDir);$(DlcvProInferIncludeDir)`。

3. 链接器 → 常规 → 附加库目录：OpenCV 的 lib 目录（`$(OpenCvLibDir)`）。
   链接器 → 输入 → 附加依赖项：`opencv_world4100.lib`（Debug 配置写 `opencv_world4100d.lib`）。`dlcv_infer_cpp.lib` 由项目引用自动添加，手工配置时自己加。
4. 源文件写 `#include "dlcv_infer.h"`。不要改用 `C:\dlcv\Lib\site-packages\dlcvpro_infer\include` 下的 C API 头，那里没有 `dlcv_infer` 命名空间和 `Result`。
5. 不要在你的工程里定义 `DLCV_INFER_CPP_EXPORTS`，那是编译 `dlcv_infer_cpp.dll` 本身用的；调用方保持默认，头文件按 `dllimport` 处理。
6. Debug/Release 要对应：Debug 工程链接 `opencv_world4100d.lib` 并配合 Debug 版 `dlcv_infer_cpp.dll`，Release 用 `opencv_world4100.lib` 和 Release 版 DLL。
7. 调用方与 `dlcv_infer_cpp.dll` 使用同一份 OpenCV 运行时（同一个 `opencv_world4100.dll`），运行时库都用 /MD（Debug 为 /MDd）。

## 输出目录与运行时文件

`dlcv_infer_cpp` 的输出目录是 `$(SolutionDir)$(Configuration)\`。把你的工程也输出到同一目录，exe 旁就自动有 `dlcv_infer_cpp.dll`；输出到别处时，在生成后事件里把 DLL 复制过去。

exe 目录需要：

- `dlcv_infer_cpp.dll`
- `opencv_world4100.dll`（Debug 为 `opencv_world4100d.dll`）
- `ZXing.dll`
- dlcvpro_infer 包里的 `dlcv_infer.dll`、`dlcv_infer_v.dll`、`haspvlib_*.dll`

## 常见错误

| 错误 | 原因 |
| --- | --- |
| MSB4019：找不到导入的项目 | `dlcv_infer_cpp\build` 目录和同级的 `build_script` 都不存在 |
| C2653 `dlcv_infer` 不是类或命名空间 | 包含目录指向了 dlcvpro_infer 的 C API 头，或没加 `dlcv_infer_cpp` 目录 |
| C1083 无法打开 `json/json.hpp` | 缺少 dlcvpro_infer 的 include 目录 |
| C1083 无法打开 `opencv2/...` | 缺少 OpenCV include 目录 |
| LNK2019 无法解析的外部符号 | 没有引用 `dlcv_infer_cpp` 工程或没有链接 `dlcv_infer_cpp.lib` |
| LNK2019 无法解析 `cv::Mat` 相关符号 | 没有链接 OpenCV 库，附加依赖项缺 `opencv_world4100(d).lib` |
| LNK2038 运行时库不匹配 | 调用方与 `dlcv_infer_cpp.dll` 的 Debug/Release 配置或 OpenCV 库版本不一致 |
| 生成后报缺少 ZXing.dll | 把 ZXing.dll 放到 `third_party\zxing-cpp\bin`，或设置 `DLCV_ZXING_DLL` |

`dlcv_infer_cpp` 的输出目录是 `$(SolutionDir)$(Configuration)\`，加入你的解决方案后放在该解决方案对应目录下。
