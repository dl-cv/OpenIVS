# 二维码与条码识别

节点类型：`features/barcode_reader`。C# 和 C++ 共用 ZXing-C++ 3.1.1；支持 QR、Data Matrix、Code128 等，不需要模型、加密狗、Python 或新的 GPU 依赖。

## 流程与参数

参考 `Test/data/barcode_flow.json`：`input/image → features/barcode_reader → output/return_json`。读码节点输入一个图像通道，输出原图像通道与读码结果通道。保存的流程端口类型为 `image_chan` / `result_chan`。

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `formats` | `""` | 空表示全部；限定格式示例 `QRCode,DataMatrix`、`Code128` |
| `try_rotate` | `true` | 尝试旋转方向 |
| `try_invert` | `true` | 尝试反色；部分码制支持 |
| `enhance` | `false` | 原图未读出时先增强重试；仍无结果且允许 Data Matrix 时，继续校准码格并纠错 |

输入是 uint8 灰度、RGB 或 RGBA；非连续 ROI 按真实行步长读取，不改输入。不合法图像或参数报错；没有识别到码返回空目标列表。每张图可以返回多个码。

读码先以原分辨率 `try_downscale=false` 读取，再启用 `try_downscale=true` 补扫其他位置的码。两轮结果按四角点区域合并：同码制的四角点完全一致，或交叠面积达到较小区域的 80% 时，保留原分辨率结果，避免同一条码在缩小层出现另一段错误文本；其他位置的有效码继续保留，包括文本相同的多个码。默认只扫描原图。开启 `enhance` 且原图两轮均未读出时，将灰度图转为浮点，做 3×3 均值滤波和 9×9 高斯模糊（σ=2），将均值图 `S` 和高斯模糊图 `G` 按 `4.5S - 3.5G` 合成，四舍五入并限幅为 uint8，再交给 ZXing 重试。重试沿用 `formats`、旋转和反色参数，不改变图像尺寸。

增强图仍无结果时，32×32 ECC200 Data Matrix 使用以下处理：

1. 利用实心边和交替边校准格子位置，采样并估计每个位置的黑、白亮度。流程图像携带原图与变换矩阵时，同时从原图取样，减少裁剪转正带来的插值损失。
2. 每个数据格保留有符号数值：负数为黑，正数为白，绝对值越小越不确定。98 个码字对应 784 个数据位，其中 36 个码字提供校验关系。
3. 先选出低可信且互相独立的 288 个数据位，用二元校验方程求解；再组合尝试其他位置，选取搜索范围内修改代价较小的候选。代价是所有被改动位置的可信程度之和，校验数据由标准有限域运算生成。
4. 两份黑白判断不同的采样恢复出相同完整码字后，把码图交给现有 ZXing 解析。输出四角来自实际图像中的网格，随后按原有坐标变换映射回原图。

这部分逻辑保留旋转、反色和码制参数。其他尺寸和码制继续由原有 ZXing 读取。AI 定位流程使用 `实例分割 → 掩码转旋转框 → 按旋转框裁剪转正 → 二维码与条码识别`，传递已有 `ModuleImage` 可保留原图及坐标变换。

结果中 `category_name` 是 HRI 解码文本，`category_id=0`，`score=1` 表示读码成功。`extra_info.barcode_format` 保存码制名称，`extra_info.polyline` 保存首尾闭合的四角点列。模块内部 bbox 为 XYWH，公开流程 JSON 为原图 XYXY；裁剪/变换由既有结果输出节点映射。读码结果不生成像素 mask。

目前测试确认：旋转 QR / Data Matrix / Code128 可读，反色 QR / Data Matrix 可读；ZXing-C++ 3.1.1 的反色扫描跳过 1D reader，**反色 Code128 返回空结果**。`try_invert` 不承诺消除此限制。二进制负载采用 HRI 展示，此节点不提供原始字节接口。

## 依赖与部署

还原 `DlcvCsharpApi/packages.config` 的 `ZXingCpp 0.5.3` 到解决方案 `packages` 目录。C# 使用官方 netstandard2.0 包装器；C++ 优先从 `dlcv_infer_cpp.dll` 所在目录延迟加载 win-x64 `ZXing.dll`，加载失败后尝试 `C:\dlcv\bin\ZXing.dll`，不引入 ZXing 的 C++ STL ABI。版本升级时必须同时核对 C ABI 和跨语言回归。

构建目标自动传播 `ZXingCpp.dll`（C#）、`ZXing.dll` 与许可证文件，正式打包白名单也包含这些文件。仅部署 win-x64，不把包中 Linux/macOS/ARM 运行时带入产品。两个 DLL 合计 3,173,376 字节，约 **3.03 MiB**。详见 `third_party/zxing-cpp/README.md`。

码格校准与纠错源码统一维护在 `dlcv_infer_cpp/native/datamatrix/`。C++ 将其编入原库；C# 使用同源构建的内部 `dlcv_datamatrix_native.dll`，由原有软件包携带，并使用项目已有的 OpenCV 运行库。dlcv_test 构建通过 `DLCV_DATAMATRIX_NATIVE_DIR` 指定该工程的产物目录，将同一个内部 DLL 放入原软件包。运行不需要 `reedsolo` 或单独的 Python 运行库包。

## 自动与人工测试

所有命令从仓库根目录执行。日常构建入口：

```powershell
C:\dlcv\python.exe build_script/build.py Test/DlcvCSharpTest/DlcvCSharpTest.csproj
C:\dlcv\python.exe build_script/build.py Test/dlcv_infer_cpp_test/dlcv_infer_cpp_test.vcxproj
```

两个控制台程序均支持：

```text
barcode-selftest <manifest.json> <flow.json> <output.json>
```

manifest 是 `[{"name":"sample","path":"图片绝对路径"}]`，flow 使用 `Test/data/barcode_flow.json`。可选 `original_path` 指定原图，`original_to_roi` 为按行排列的 6 个原图到裁图仿射系数。普通图像报告包含模块局部结果和公开流程结果；携带原图的用例使用正式 `ModuleImage` 验证模块，完整 AI 流程另用模型推理入口验证。退出码 0 表示执行和内置校验成功，业务文本另与独立参考逐字比较。图片与报告使用工作目录，不提交客户图或文本。

使用已安装 `zxing-cpp==3.1.1`、numpy 和 opencv-python 的 Python 执行合成样例的内容和坐标验证：

```powershell
python Test/verify_barcode.py --output-dir "$env:TEMP/barcode-tests" --cs-exe Test/DlcvCSharpTest/bin/x64/Debug/DlcvCSharpTest.exe --cpp-exe Debug/dlcv_infer_cpp_test.exe
```

测试脚本从 `Test/data/barcode/` 读取固定 QR / Data Matrix / Code128 SVG 并栅格化；低对比条码与混合尺寸双二维码由测试脚本生成，不依赖外部样图。

覆盖灰度/RGB/RGBA、非连续 ROI、旋转/反色、中文文本、多码、空白、过滤、非法参数、重复调用、低对比度 Data Matrix 开关增强的差异、开启增强后小码仍优先读取原图，以及原分辨率已找到一个码时仍能补回另一位置的码；同时执行实际流程，不只测试 DLL 导出符号。

C# 和 C++ 软件包分别使用 `1_编译打包.bat`、`1_编译打包(C++).bat`。两个安装脚本均支持 `--target <目录>`，默认安装前检查现有包文件是否被占用。
