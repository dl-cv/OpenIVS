# 二维码与条码识别

节点类型：`features/barcode_reader`。C# 和 C++ 共用 ZXing-C++ 3.1.1；支持 QR、Data Matrix、Code128 等，不需要模型、加密狗、Python 或新的 GPU 依赖。

## 流程与参数

参考 `Test/data/barcode_flow.json`：`input/image → features/barcode_reader → output/return_json`。读码节点输入一个图像通道，输出原图像通道与读码结果通道。保存的流程端口类型为 `image_chan` / `result_chan`。

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `formats` | `""` | 空表示全部；限定格式示例 `QRCode,DataMatrix`、`Code128` |
| `try_rotate` | `true` | 尝试旋转方向 |
| `try_invert` | `true` | 尝试反色；并非所有码制都支持 |
| `enhance` | `false` | 普通 ZXing 与直方图回退为空时，对 32×32 DataMatrix 执行 DPM 增强和 GF(2) 软判决恢复 |

输入是 uint8 灰度、RGB 或 RGBA；非连续 ROI 按真实行步长读取，不改输入。不合法图像或参数报错；没有识别到码返回空目标列表。每张图可以返回多个码。

读码先以原分辨率 `try_downscale=false` 读取，再启用 `try_downscale=true` 补扫其他位置的码。两轮结果按四角点区域合并：同码制的四角点完全一致，或交叠面积达到较小区域的 80% 时，保留原分辨率结果，避免同一条码在缩小层出现另一段错误文本；其他位置的有效码继续保留，包括文本相同的多个码。两轮仍为空时，才对当前图转灰度并做直方图均衡，增强图使用相同的读码和合并规则。各轮沿用同一 `formats`、旋转和反色参数，输出坐标仍对应原图尺寸。

`enhance=true` 时，只有普通路径仍为空且 `formats` 允许 DataMatrix，才进入 DPM 回退。回退使用局部高光抑制、双尺度中值、形态学平场、DoG 去串扰、8-DOF 时钟锁定与 GF(2) OSD 恢复，再交给 ZXing-C++ 解码。普通 QR/Code128 行为不变；当前恢复内核针对 32×32 DataMatrix。

C# 和 C++ 都支持此开关。C++ 内核位于 `dlcv_infer_cpp/flow/modules/dpm/`，直接编入推理 DLL，不调用 C# 或 Python；保留 C# 的 float32 运算顺序、图像边界处理和候选遍历次序，该编译单元使用严格浮点模式。增强结果新增 `extra_info.dpm_decode_mode`、`dpm_enhance_ms`、`dpm_total_ms`；DPM 成功时几何范围为输入裁图，失败仍返回空列表。等价范围是相同输入裁图；完整流程还受上游分割、旋转框和裁图实现影响，不能以单模块相同推断整条流程相同。

结果中 `category_name` 是 HRI 解码文本，`category_id=0`，`score=1` **只表示读码成功，不是模型置信度**。`extra_info.barcode_format` 保存码制名称，`extra_info.polyline` 保存首尾闭合的四角点列。模块内部 bbox 为 XYWH，公开流程 JSON 为原图 XYXY；裁剪/变换由既有结果输出节点映射。没有真实像素 mask，不把四边形伪装成分割 mask。

目前测试确认：旋转 QR / Data Matrix / Code128 可读，反色 QR / Data Matrix 可读；ZXing-C++ 3.1.1 的反色扫描跳过 1D reader，**反色 Code128 返回空结果**。`try_invert` 不承诺消除此限制。二进制负载采用 HRI 展示，此节点不提供原始字节接口。

## 依赖与部署

还原 `DlcvCsharpApi/packages.config` 的 `ZXingCpp 0.5.3` 到解决方案 `packages` 目录。C# 使用官方 netstandard2.0 包装器；C++ 优先从 `dlcv_infer_cpp.dll` 所在目录延迟加载 win-x64 `ZXing.dll`，加载失败后尝试 `C:\dlcv\bin\ZXing.dll`，不引入 ZXing 的 C++ STL ABI。版本升级时必须同时核对 C ABI 和跨语言回归。

构建目标自动传播 `ZXingCpp.dll`（C#）、`ZXing.dll` 与许可证文件，正式打包白名单也包含这些文件。仅部署 win-x64，不把包中 Linux/macOS/ARM 运行时带入产品。两个 DLL 合计 3,173,376 字节，约 **3.03 MiB**。详见 `third_party/zxing-cpp/README.md`。

## 自动与人工测试

所有命令从仓库根目录执行。日常构建入口：

```powershell
C:\dlcv\python.exe build_script/build.py Test/DlcvCSharpTest/DlcvCSharpTest.csproj
C:\dlcv\python.exe build_script/build.py Test/dlcv_infer_cpp_test/dlcv_infer_cpp_test.vcxproj
```

两个控制台程序均支持：

```text
barcode-selftest <manifest.json> <flow.json> <output.json>
```

manifest 是 `[{"name":"sample","path":"图片绝对路径"}]`，flow 使用 `Test/data/barcode_flow.json`。退出码 0 表示执行和内置校验成功，非 0 表示失败；报告含每图的模块局部结果和公开流程结果。**自有样图的业务文本须人工检查或由调用者断言**，不能只看退出码认为内容符合预期。图片与报告放系统 TEMP，不提交客户图或文本。

可在独立 Python 环境安装 `zxing-cpp==3.1.1`、numpy、opencv-python 后执行合成样例的内容/坐标一致性验证：

```powershell
python Test/verify_barcode.py --output-dir "$env:TEMP/barcode-tests" --cs-exe Test/DlcvCSharpTest/bin/x64/Debug/DlcvCSharpTest.exe --cpp-exe Debug/dlcv_infer_cpp_test.exe
```

测试脚本从 `Test/data/barcode/` 读取固定 QR / Data Matrix / Code128 SVG 并栅格化；低对比度 EAN-13 与混合尺寸双二维码由测试脚本生成，不依赖外部样图。

覆盖灰度/RGB/RGBA、非连续 ROI、旋转/反色、中文文本、多码、空白、过滤、非法参数、重复调用、低对比度 EAN-13 回退，以及原分辨率已找到一个码时仍能补回另一位置的码；同时执行实际流程，不只测试 DLL 导出符号。

这不是完整安装包发布；正式打包仍走 `1_编译打包.bat`，安装须单独授权。

### DPM 跨语言验证

两个控制台程序支持 `dpm-selftest <manifest.json> <output.json>`。manifest 为 `{"crops":[{"name":"crop-0","path":"裁图绝对路径"}, ...]}`，至少四张；可追加 `model`（原 DVST 路径）与 `images`（同结构原图列表）执行完整流程。输出目录分别指定，增强 PNG 与 JSON 存在同一目录。测试包含四线程冷启动、串行对照、实际模块的非连续输入、输入像素不被修改；并发计时包含直接增强和模块再次读码，不等于一次四码节点耗时。

```powershell
Test/DlcvCSharpTest/bin/x64/Release/DlcvCSharpTest.exe dpm-selftest manifest.json cs/report.json
Release/dlcv_infer_cpp_test.exe dpm-selftest manifest.json cpp/report.json
python Test/verify_dpm.py --cs cs/report.json --cpp cpp/report.json --output comparison.json
```

比较增强 PNG 的每个像素、恢复模式、模块全部非耗时字段，并报告完整流程的文本、数量和结果差异；任一全流程差异返回非零。仅验证相同裁图时显式加 `--crops-only`。真实输入及输出报告不提交仓库。完整流程失败不能记为全量通过，不能为提高通过率静默修改上游 ROI。
